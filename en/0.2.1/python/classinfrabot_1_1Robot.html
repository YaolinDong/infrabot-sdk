Controller parameters

[Blocking, about 10 ms per parameter] Firmware with INFRABOT_CAP_PARAMETERS (protocol 1.1): the gravity, impedance and admittance settings that the touchscreen sliders change.

Every parameter describes itself (name, unit, range, default, slew rate), so no table is compiled into the SDK. set_parameter() stores the requested value and the controller slews its applied value toward it, so a write never steps a gain. Values live in RAM and return to their defaults at reboot. Reading is open to any PC; writing needs the PC that controls the arm, or no controlling PC.

Detailed Description

The client for one arm controller.

Robot(address="192.168.0.50", command_port=5001, telemetry_port=5000) creates the client; connect() opens the sockets. It runs a receive thread and a 1 kHz service thread (heartbeat, NRT session, native joint stream). Calls release the GIL. A call that fails raises RuntimeError with the reason, in Chinese.
