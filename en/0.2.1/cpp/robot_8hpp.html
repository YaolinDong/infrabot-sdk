Detailed Description

The C++ API of the InfraBot SDK: one Robot per arm controller.

The SDK is the PC side of the controller's UDP protocol (infrabot/protocol.h).

Timing classes
Every function is tagged with how it behaves:
  • [Blocking] waits for the controller (a reply or telemetry), at most the time given. Never call it from a 1 kHz loop.
  • [Non-blocking] returns at once: it sends one datagram or copies state.
  • [RT] non-blocking and allocation-free on success: safe in a 1 kHz loop.

A function that fails returns false (or a result code) and says why in error. The messages are in Chinese.

Lifecycle
connect() → set_motor_profile() (drives disabled, IDLE; runs the controller's parameter self-check) → servo_on() → switch_mode() → commands → stop() or switch_mode(Mode::Idle) → servo_off().

While connected the SDK keeps the controller alive in IDLE and the NRT modes (a 100 Hz heartbeat and the movej/movep session). In the RT modes servej() or servep() must keep coming (at least 10 Hz, normally 1 kHz), or opt into start_joint_stream() and refresh servej() within its producer timeout.

A controller whose PC goes quiet (program closed, cable pulled) stops the arm in a controlled way and holds it enabled. It never disables the drives by itself (firmware with INFRABOT_CAP_CONTROLLED_STOP; older firmware disables).
